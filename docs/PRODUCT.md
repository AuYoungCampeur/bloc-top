# BlocTop 产品迭代与验收

> 2026-10-02 启动持续产品迭代。用户授权 PM/Team Lead 组建开发团队、提出需求并改进 UI、后端与工程基础。当前产品尚未通过完整成熟度验收；静态检查、局部测试和部署成功不能代替真实业务流程验收。

## 产品定位与工作顺序

面向户外抱石攀岩者提供可信、可查找、可离线使用的岩场与 Topo 资料；为岩场管理员提供安全、高效的内容维护工具。两个应用共同构成产品，优先完善后台，所有后台内容变更都要检查用户端的可见性。

核心管理流程：登录/授权 → 选择岩场 → 区域与岩面 → 线路与多图 Topo → Beta → 用户端发布。核心用户流程：选择城市/岩场 → 搜索筛选线路 → 阅读 Topo/Beta → 下载离线 → 离线访问与更新。

PM/Team Lead 负责优先级、数据边界、架构评审与集成验收；后端、后台体验、用户端质量三个开发方向分别实现独立任务。以用户影响和可验证证据安排迭代，不以代码数量衡量进度。

## 当前迭代

### 1. 登录、写入与编辑状态基础

- 两端共用环境感知的认证配置，修复 localhost Cookie 域/可信来源，保留生产共享会话；隔离 Vercel preview Cookie。
- 统一 Beta API，补齐后台 POST 认证、原子去重、缺失记录响应和可选字段清除；保留即时展示和 `no-store`。
- 线路工作台保存后采用服务端记录作为基线，Beta 更新不覆盖未保存的 Topo/表单；多图脏状态比较包含区域。
- Service Worker 仅缓存明确公开的 GET，认证、账号、权限和管理 API 直接走网络；升级清理旧通用 API 缓存。
- 工程验证：补齐 Editor 图片压缩依赖、路由类型自动生成和两端提交 lint；使用根 frozen install 核查工作区依赖链接。

验收：业务回归测试、实际认证库隔离存储集成测试、类型/lint、双应用构建；完成前不记为已发布。

### 2. 内容一致性与可靠发布

- 共享岩面引用服务：覆盖新旧字段、区域隔离、多图标注和跨存储部分失败，先保护原文件与引用再移除旧对象。
- 线路数字 ID 使用持久原子计数器，删除不回收数字；首次只能参考现存最大值，未知历史删除 ID 无法还原。
- 权限查询、岩场字段验证、授权对象存在性以及各端同名 API 的政策统一。
- 写入到 PWA 重验证采用有限时长且受运行时保障的调用，补齐路径覆盖，记录结果和失败恢复。

### 3. 后台工作流与反馈

- 从岩场详情进入该岩场的岩面/线路管理；刷新和深链接保持上下文。
- 完成新建岩场流程的代码评审与验收，集成现有工作区实现。
- 列表与表单有明确加载/错误/空态，保存和失败反馈一致；离开保护覆盖全部编辑入口。
- 修复同名岩面分组，补管理界面的可访问性和窄屏使用验收。

### 4. 用户端与离线产品

- 下载按真实 Topo 引用收集图片并准确统计完成/失败，支持重试和更新。
- 验证登录/Beta完整流程、跨线路请求竞态、三语文案、搜索导航和离线阅读。
- 根据实际流程补充可恢复错误反馈与必要的产品能力，避免先堆无验收的新功能。

### 5. 发布与运营

- 修正工程验证入口，补双应用 CI 和隔离数据端到端测试。
- 形成可执行的部署、回滚、配置检查、日志与数据恢复说明；执行成熟度审查。
